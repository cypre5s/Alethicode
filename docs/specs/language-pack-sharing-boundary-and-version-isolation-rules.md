# 语言包共享边界与版本隔离规则

本文档是语言包（`language_pack`）、班级（`classroom`）与版本线之间共享边界的正式规则说明。所有涉及语言包发布、班级绑定、内容修改的开发行为必须遵守本文档约束。

---

## 一、核心关系模型

### 1.1 语言包（`language_pack`）

语言包是**共享课程母版**，也是**版本线**的载体。

职责范围：

- 课件文档与页内容
- 章节与知识组件（KC）
- 发布后的正式题目集合
- QA 检索范围
- 一条可持续演进的版本线（同一 `slug` 下多个 `version`）

语言包**不是**班级运行态容器，不承载任何班级维度的运行数据。

### 1.2 班级（`classroom`）

班级是**开课实例**，也是**教学运行容器**。

职责范围：

- 班级成员与角色
- 班级自己的课件副本与展示顺序（`classroom_lesson`）
- 班级题目可见性与教学安排（`classroom_problem`）
- 作业、提交、学习记录、课堂监控与协作状态

班级**不是**内容母版，班级层的任何数据变更不允许回写到语言包母体。

### 1.3 "课程"

当前系统不单独建模 `Course` 实体。语言包承担课程模板职责，班级承担开课实例职责。

## 二、发布态与草稿态分离

### 2.1 状态定义

| 状态 | 含义 | 允许的操作 |
|------|------|-----------|
| `draft` | 草稿，正在通过 init pipeline 构建 | 文档上传、解析、KC 提取、示例提取、题目生成、验证 |
| `published` | 已发布，可被班级绑定和学生消费 | 只读，不允许任何内容修改 |

### 2.2 规则

1. **已发布版本只读**：一旦语言包 `status` 变为 `published`，其内容（文档、页、章节、KC、示例、题目映射）全部冻结，不允许任何修改。
2. **修改只能发生在草稿上**：所有内容变更必须通过创建新版本草稿（`createTask`）进行，新版本 `version = max(version) + 1`，初始状态为 `draft`。
3. **Init pipeline 是唯一修改路径**：语言包内容的创建和修改只通过 init task pipeline 的阶段推进完成（`created → normalizing → parsing → kc_ready → segments_ready → units_ready → oj_candidates_ready → problem_packages_ready → problems_validated → published`）。
4. **不允许逆向发布**：`published` 不在阶段转换表中作为源状态，已发布的 init task 不可恢复（`restoreStage` 显式拒绝 `published` 状态）。

## 三、版本线与班级绑定

### 3.1 版本线语义

同一个 `slug` 下可以有多个版本（`version`），每个版本是独立的 `language_pack` 记录。版本线的演进通过创建新的 init task 自然推进。

### 3.2 班级绑定规则

1. **一个班级只绑定一个语言包**：`classroom_language_pack` 表上有唯一索引 `uq_classroom_language_pack_classroom(classroom_id)`，保证单班级单绑定。
2. **班级创建时绑定**：班级创建时指定 `language_pack_id`，系统将课件和题目导入到班级自己的运行表中。
3. **绑定后冻结**：班级创建后，其绑定的语言包版本不会因为同 `slug` 发布新版本而自动变更。

### 3.3 发布不触发 rebinding（核心规则）

**发布新版本时，不会自动将历史班级的绑定切换到新版本。**

具体行为：

- 发布新版本只产生一个新的可选版本
- 历史班级保持原绑定不动
- 新建班级可以绑定新发布版本
- 旧班级不发生无感切换

这条规则消除了以下结构性风险：

| 风险 | 说明 |
|------|------|
| 跨老师干扰 | 老师 A 发布新版本，不会影响老师 B 已开课班级 |
| 教学节奏漂移 | 历史班级的内容证据和教学进度不会在中途被替换 |
| 版本语义不可追踪 | QA、知识图谱、班级运行上下文的版本来源始终明确 |

### 3.4 班级升级语言包

当前系统**不提供**班级升级语言包的功能。如果未来需要：

- 必须设计为**显式操作**（老师主动触发）
- 升级前后必须保留清晰的版本切换语义
- 不允许因为 `slug` 相同而自动迁移

## 四、共同维护规则

### 4.1 多老师协作

多个老师可以共同维护同一条语言包版本线，但协作必须遵守以下约束：

1. **协作对象是下一版草稿**：多个老师共同维护只允许发生在 `draft` 状态的语言包上（即通过 init task pipeline 构建中的新版本）。
2. **不允许直接改已发布包**：已发布语言包的内容冻结，不提供任何修改入口。
3. **版本线只增不减**：不删除已发布的历史版本，保证历史班级的绑定关系始终有效。

### 4.2 权限边界

- 语言包的可见性和操作权限按 `language_pack` 的所有者和共享配置控制
- AI 授权按班级绑定的语言包计算，不按"用户能看到哪些全局包"裸算
- 共享语言包不会天然导致统计、问答、知识图谱跨班级串读

## 五、班级运行态隔离

### 5.1 数据流向

```
语言包（母版）──创建班级时导入──▶ 班级运行态（副本）
                                      │
                                      ▼
                              学生消费、作业、提交
                                      │
                                      ▼
                              学习记录、监控数据
                                      │
                                      ✘ 不回写到语言包
```

### 5.2 隔离规则

| 数据类型 | 所在表 | 归属层 | 是否回写母包 |
|----------|--------|--------|-------------|
| 班级课件副本 | `classroom_lesson` | 班级 | 否 |
| 班级题目可见性 | `classroom_problem` | 班级 | 否 |
| 作业安排 | 班级相关表 | 班级 | 否 |
| 学习记录 | 提交相关表 | 班级 | 否 |
| 课堂监控 | 班级相关表 | 班级 | 否 |
| 课件文档 | `language_pack_document` | 语言包 | 不接受班级写入 |
| 页内容 | `language_pack_page` | 语言包 | 不接受班级写入 |
| KC 定义 | `language_pack_kc` | 语言包 | 不接受班级写入 |
| 题目映射 | `language_pack_problem_mapping` | 语言包 | 不接受班级写入 |

### 5.3 ClassroomServiceImpl 中无回写路径

`ClassroomServiceImpl` 中不存在任何 `INSERT INTO language_pack*` 或 `UPDATE language_pack*` 语句。班级层的所有写操作都指向 `classroom_*` 表。

## 六、污染判定标准

任何"共享包被污染"的判断都必须落到具体链路，至少回答以下三个问题：

1. **是否改动了已发布母包？** 已发布语言包的内容（文档、页、KC、示例、题目映射）是否被修改。
2. **是否让历史班级隐式切到了别的版本？** 已开课班级的 `classroom_language_pack.language_pack_id` 是否在非显式操作下发生变更。
3. **是否让统计、问答或知识分析跨班级串读？** 一个班级的 AI 查询、可见包范围、知识图谱是否读取到了其他班级的运行态数据。

只要这三条都被硬性约束住，共享语言包就不构成污染问题。
