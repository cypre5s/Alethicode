## 1 作品简介

Alethicode 是一个面向初学者的 LLM 驱动智能教育平台，核心亮点是 **AI 导学助手** 与 **教学闭环**。AI 导学助手内嵌在做题页面中，按“审题→构思→编码→诊断→复盘→迁移”六阶段为学生提供结构化的过程性引导；教学闭环则把做题、导学、课件问答、错题复习和教师学情分析串联为“学→练→诊→复→析”的完整链路，目标不是停留在单点答疑工具，而是让每个教学环节的数据都能流入下一个环节。

从当前仓库和前端公开入口来看，系统已经形成 5 条稳定主线：

- 做题页内嵌 **AI 导学助手**，围绕审题、构思、编码、错误诊断、通过复盘、迁移练习 6 个阶段提供结构化帮助
- 课件问答页支持基于课程内容包的引用式问答，回答会回链到课件证据页
- 错题本与专项复习包闭合**教学闭环**中“诊→复”环节，帮助学生记录错误、生成反思、追踪“已攻克/待攻克”状态
- 班级模块支持课件、题目、作业与教师侧学情数据看板
- 管理后台支持用户与公告管理、题目管理、知识图谱管理、AI 变体题审核、12 阶段语言包初始化管线、Judge Server 状态查看与 API 文档查看

当前仓库技术规模可直接从源码统计验证：后端 `362` 个 Java 源文件（约 58,352 行）、前端 `104` 个 Vue 组件和 `74` 个 JS 模块、数据库 `50` 个 Flyway 迁移脚本、后端控制层 `307` 个映射端点。技术栈采用 Spring Boot 3.4.4 + Java 21 + Vue 3 + Vite 7 + PostgreSQL/pgvector + Redis。

需要特别说明的是，比赛材料仅描述当前项目中可核验、可演示、可从前端主流程到达的能力；不把仓库中的隐藏入口或实验性展示页面作为本作品主卖点。

## 3 设计思想

### 3.1 项目背景

非计算机专业学生进入编程学习时，常见问题并不是“没有题做”，而是“不知道题目在考什么、卡住以后不知道下一步做什么、做错以后只看到 WA 却不知道错在哪”。与此同时，教师往往也缺少稳定的学情证据，难以快速定位学生的薄弱点和教学盲区。

Alethicode 的设计起点因此很明确：

- 对学生，要把判题结果转化为可执行的学习反馈
- 对教师，要把零散的提交、错题和课件使用行为转化为可读的教学数据
- 对课程资源，要让课件不只用于展示，还能成为问答和练习生成的依据

### 3.2 设计构思与创意

本作品的核心思路围绕两个关键词展开：**AI 导学助手** 和 **教学闭环**。AI 导学助手把 LLM 从“聊天窗口”收敛为做题过程中各司其职的专职教学 Agent；教学闭环把 AI 导学能力延伸到做题页面之外，串联起学生学习与教师教学的完整链路。

- 在做题页，AI 不直接替代学生写代码，而是按阶段给出审题、思路、诊断、复盘和迁移提示
- 在课件侧，系统不是泛化问答，而是先把课件加工成结构化课程内容包，再基于证据页回答问题
- 在复习侧，系统把错题、根因、反思和再练串起来，形成面向初学者的学习闭环
- 在教师侧，系统把班级提交、知识点掌握度和风险信号组织成可操作的数据看板

### 3.3 项目模块与功能

| 模块 | 当前可核验功能 |
|------|---------------|
| **学习任务与评测** | 题目浏览、代码提交、自动判题、提交记录、Python3/C/C++/Java 多语言支持 |
| **AI 导学助手** | 做题页 6 阶段导学、6 个 Agent（含 1 个编排调度 + 5 个专职教学）、11 类结构化卡片、错误诊断与通过复盘质检 |
| **课件知识问答** | 12 阶段课程内容包初始化管线、课件页检索、带引用回答、后台初始化任务管理 |
| **错题与教学闭环** | 个性化错题本、AI 生成反思、专项复习包、首页学习仪表盘，闭合“诊→复”教学链路 |
| **课堂教学** | 班级、成员、课件、题目（含 AI 生成题目）、作业、教师学情看板、风险学生画像 |
| **系统管理** | 用户、公告、系统与 AI 服务配置管理、Judge Server 状态查看、知识图谱管理、AI 变体题审核、题目管理、Swagger API 文档 |

### 3.4 技术运用与特色

**AI 导学助手的实现特点：**

- 后端工作流当前围绕 `READING / IDEATING / CODING / ERROR_FEEDBACK / AC_REVIEW / TRANSFER` 6 个阶段组织
- 系统注册了 6 个 Agent：`OrchestratorAgent` 负责编排调度，`GuideAgent`、`DiagnosticsAgent`、`TransferAgent`、`MetacognitiveAgent`、`ChatAgent` 5 个专职 Agent 处理不同类型的教学任务
- `CardType` 枚举定义了 11 类结构化输出，覆盖审题导学、思路分析、错误诊断、执行跟踪、通过复盘、迁移练习等场景
- `ReflectionService` 用于对关键教学输出做结构和内容层面的再检查，提高结果稳定性

**课件问答与课程内容包的实现特点：**

- 管理后台提供 12 阶段语言包初始化管线，把课件加工为页面文本、知识点、教学单元和可发布的问题资源
- 问答链路采用关键词检索与向量检索结合的方式组织证据页，并在前端展示引用来源
- 仓库中保留了 `REACT_ENABLED`、`QA_GROUNDING_CRITIC_ENABLED` 等 Beta 开关，但默认比赛叙事不把这些实验能力视为主流程

**整体工程特点：**

- Spring Boot 3.4.4 + Java 21 负责主要业务逻辑
- Vue 3 + Vite 7 + Element Plus + CodeMirror 6 负责学生端与管理端前端
- PostgreSQL/pgvector + Redis 提供数据存储、检索与会话支撑
- `start.sh` 已串联本地启动所需的 PostgreSQL、Redis、后端、Judge 与前端开发环境
- `/api/docs` 可直接验证接口形态，后台可直接查看语言包与判题服务状态
