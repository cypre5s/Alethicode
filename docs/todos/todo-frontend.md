## 第 3 步：在 `frontend` 中实施 Vue3 升级

迁移原则：

### 3.1 依赖升级策略
优先采用“**最小破坏、最大兼容**”的升级方案：

- 升级 `vue` 到 Vue3
- 升级 `vue-router` 到 Vue Router 4
- 状态管理优先采用与旧项目最接近的方案
  - 如果旧项目使用 vuex，优先迁移到 Vuex 4，而不是顺手改成 Pinia
  - 除非 Vuex 4 无法满足兼容要求，否则不要擅自替换状态管理方案
- 若旧项目深度依赖 Vue2 API，可优先考虑 `@vue/compat` 过渡方案
- 对 UI 组件库采用“页面不变样优先”策略：
  - 如果旧项目使用 Element UI，优先评估兼容路线
  - 如需切换到 Element Plus，必须尽最大努力保持视觉样式与旧版一致
  - 若切换组件库会导致明显样式变化，则应增加样式兼容层或局部封装，避免 UI 变化
- 保留原有 CSS 预处理器和样式组织方式
- 不要因为升级而顺手把 Options API 全改成 Composition API
- **默认保留原写法**，只在必须时做 Vue3 兼容改造

### 3.2 代码迁移策略
对以下内容进行系统迁移：

1. 入口文件
   - `new Vue(...)` -> `createApp(...)`
   - 全局插件、全局组件、全局指令、全局属性迁移

2. 路由
   - `new Router(...)` -> `createRouter(...)`
   - `mode` 迁移
   - 动态路由、路由守卫、权限逻辑保持一致
   - 菜单高亮、面包屑、keep-alive 行为不可变化

3. 状态管理
   - `Vue.use(Vuex)` 相关逻辑迁移
   - modules、getters、actions、mutations 行为保持一致
   - 不改变业务状态结构

4. 组件 API 兼容
   - 处理废弃/变化 API
   - 处理 `.sync`
   - 处理 `v-model` 改动
   - 处理 `$listeners` / `$attrs`
   - 处理 filters
   - 处理插槽语法变化
   - 处理生命周期钩子变化
   - 处理事件发射和接收方式差异
   - 处理 ref 获取时机差异

5. 原型链与全局方法
   - `Vue.prototype.$xxx` -> `app.config.globalProperties.$xxx`
   - 确保 this 调用行为兼容

6. 第三方库
   - 对不兼容 Vue3 的库进行升级、兼容封装或最小替换
   - 替换时必须保证页面输出和交互体验不变
   - 替换前先定位该库影响的页面与功能点

7. 样式与 DOM 结构
   - 绝对不能大面积改 class 名、层级结构、容器结构
   - 尽量保持模板结构不变
   - 避免因组件替换导致 DOM 层级变化过大
   - 若第三方组件升级导致默认样式不同，必须通过补丁样式恢复旧观感
   - 所有修复应优先局部精准处理，避免全局污染

### 3.3 编译与构建
- 修复所有编译报错
- 修复所有运行时报错
- 修复所有明显告警，尤其是可能导致行为差异的兼容告警
- 保持原有环境变量机制、代理配置、别名配置、打包输出习惯尽量一致
- 若构建工具必须调整，也要做到“对业务代码影响最小”
