# OJ 前端统一到 Element Plus 的分批迁移计划（按业务域）

## 摘要
本计划采用你确认的策略：按业务域分批、迁移窗口冻结、验收以“功能正确 + 关键视觉一致”为准。  
执行方式是“批次内彻底替换，不保留双命名并行路径”，每批完成后立即通过统一门禁，再进入下一批。

## 关键接口与规范变更
1. 全局 UI 运行时从 `ViewUIPlus` 切换为 `ElementPlus`，OJ 入口不再 `app.use(ViewUIPlus)`。  
2. OJ 全局消息/弹窗/加载调用统一到 Element Plus 对应能力（例如消息、确认框、加载服务），不再使用 ViewUI 全局对象语义。  
3. OJ 组件事件与绑定语义统一到 Element Plus（移除 `@on-*` 风格、ViewUI 专属 props）。  
4. 图标体系从 `ios-*` 名称切换为 `@element-plus/icons-vue` 组件。  
5. i18n 中移除 `view-ui-plus` 语言包合并，仅保留业务文案 + `element-plus` 语言包。  
6. 清理 `view-ui-plus` 依赖与 `.ivu-*` 样式体系（包含主题桥接和测试选择器）。

## 统一门禁（每一批都必须通过）
1. 静态门禁：该批次作用域内 `view-ui-plus|ViewUIPlus|.ivu-` 扫描结果为 `0`。  
2. 质量门禁：`npm run lint` 通过；该批次对应单测与 e2e 套件全部通过。  
3. 业务门禁：该批次定义的关键用户路径手工回归通过（见各批次验收标准）。  
4. 视觉门禁：该批次关键页面视觉对比通过，阈值定义为“无阻断视觉问题（错位、遮挡、不可点击），且关键页面 diff <= 2%”。

## 分批计划与批次验收标准
### Batch 0（准备批，2-3 天）
更改计划：冻结 OJ 迁移范围内新需求；建立组件映射清单（ViewUI -> Element Plus）；建立批次扫描脚本与 CI 门禁；锁定关键页面视觉基线与 e2e 基线。  
验收标准：门禁脚本可独立执行并用于 CI；迁移范围冻结生效；关键页面基线截图与回归脚本可重复执行。

### Batch 1（用户与站点框架域，3-5 天）
更改计划：迁移登录/注册/找回密码/导航与用户下拉等站点壳层；替换 Form/Input/Button/Menu/Dropdown/Modal/Icon；统一全局消息提示调用。  
验收标准：登录、注册、登出、跳转设置、语言切换全部可用；认证相关 e2e 全绿；该域内不再出现 ViewUI 依赖与 `.ivu-*` 类选择器。

### Batch 2（题目练习域，4-6 天）
更改计划：迁移题库列表、题目详情、代码编辑器页及相关卡片；替换 Table/Pagination/Select/Tag/Tooltip；修正筛选、分页、标签交互事件。  
验收标准：题目检索、筛选、分页、进入题目、提交前编辑流程通过；题目域单测与回归通过；关键页面视觉无结构性漂移。

### Batch 3（提交与错题本域，3-5 天）
更改计划：迁移提交列表、提交详情、错题本；重点替换表格列渲染、状态标签、筛选下拉、分页、弹窗与操作按钮。  
验收标准：状态筛选、分页、详情查看、分享/取消分享、错题记录新增与筛选可用；提交域 e2e/单测全绿；该域静态扫描归零。

### Batch 4（课堂教学域，6-9 天，最高风险）
更改计划：迁移课堂列表、详情、作业、课件管理、AI 生成题、协作编程、监控看板；重写 `h(ViewButton/ViewIcon/ViewTag)` 渲染点为 Element Plus 方案；收口课堂域复杂表格、标签和操作列交互。  
验收标准：教师与学生两种角色主路径可用；课堂核心链路（创建/加入课堂、布置作业、查看提交、AI 题目审核流程、协作页会话）通过；课堂域 websocket 相关页面交互无回归；视觉门禁通过。

### Batch 5（收尾清理与全量验收，2-4 天）
更改计划：删除 `view-ui-plus` 依赖、OJ 入口残留、i18n 残留、主题桥接残留与测试中 `.ivu-*` 选择器；统一测试断言为 Element Plus 语义；完成全量回归。  
验收标准：`package` 依赖不含 `view-ui-plus`；源码与测试（排除历史快照目录）无 `view-ui-plus|ViewUIPlus|.ivu-`；全量 lint/单测/e2e/视觉回归通过。

## 测试计划（实施时固定执行）
1. 每批执行：作用域静态扫描 + lint + 批次单测 + 批次 e2e + 批次视觉对比。  
2. 每两批执行一次：OJ 主链路回归（认证、题目、提交、课堂核心路径抽测）。  
3. 最终执行：全量回归与替换验收（功能、关键视觉、依赖纯化）。

## 默认假设（已锁定）
1. 分批方式固定为“按业务域”。  
2. 迁移期间采用“迁移窗口冻结”。  
3. 验收口径固定为“功能 + 关键视觉”，不追求每批像素级零差异。  
4. 不引入兼容性双栈，不保留旧命名并行路径；批次内直接完成统一替换。
