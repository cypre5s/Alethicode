# Alethicode 答辩 PPT 内容稿

> 建议时长：8-12 分钟  
> 建议页数：12-15 页  
> 风格建议：深色标题页 + 浅色内容页，突出“AI + OJ + 教学闭环”。  
> 说明：本文是 PPT 内容稿，可直接用于制作 `.pptx`。

## 第 1 页：标题页

标题：Alethicode 智能在线评测平台  
副标题：面向非计算机专业 Python 初学者的 AI 编程学习系统  
展示信息：课程名称、团队/姓名、日期、指导教师。

讲解要点：

1. 项目聚焦编程初学者学习困难。
2. 核心思路是把真实 OJ 判题与 AI 个性化辅导结合。

## 第 2 页：项目背景与痛点

页面内容：

| 痛点 | 具体表现 |
|---|---|
| OJ 反馈太冷 | 只告诉 AC/WA/RE，不解释原因。 |
| AI 脱离课堂 | 通用 AI 不知道教师课件和学生历史。 |
| 教师负担重 | 备题、批改、答疑、学情分析成本高。 |

讲解要点：

1. 非计算机专业学生常常不是不会写代码，而是不知道错在哪里。
2. 教师需要一个既能判题又能辅助教学的平台。

## 第 3 页：项目目标

页面内容：

1. 建设完整在线评测闭环。
2. 建设阶段化 AI Tutor。
3. 建设课件 RAG 问答。
4. 建设课堂协作和学情分析。
5. 建设可部署、可测试、可观测的工程系统。

讲解要点：

项目不是简单聊天机器人，而是“真实学习数据 + AI 辅导 + 教师管理”的综合平台。

## 第 4 页：系统总体架构

建议图示：

```text
Vue 前端
  │
Spring Boot 后端
  ├── PostgreSQL / Redis
  ├── Judge Server
  ├── tutor-graph
  ├── alethicode-rag
  └── Observability
```

讲解要点：

1. Vue 负责学生端和管理端交互。
2. Spring Boot 是主业务入口。
3. Python 微服务负责 AI 工作流和 RAG。
4. PostgreSQL、Redis、Memgraph、NATS、Temporal 支撑运行。

## 第 5 页：核心功能一：在线评测

页面内容：

1. 题目列表与题目详情。
2. CodeMirror 多语言代码编辑。
3. Judge Server 自动判题。
4. 提交记录和详情。
5. 管理端题目与测试用例维护。

演示提示：

展示一道 Python 题，从打开题面、输入代码、提交到查看结果。

## 第 6 页：核心功能二：AI Tutor

页面内容：

AI Tutor 七阶段：

1. READING 读题。
2. IDEATING 构思。
3. SCAFFOLDING 脚手架。
4. CODING 编码。
5. ERROR_FEEDBACK 错误反馈。
6. AC_REVIEW 通过复盘。
7. TRANSFER 迁移练习。

讲解要点：

AI Tutor 根据题目、学生提交、错误信息、学习者画像和课件上下文进行辅导，不是简单调用模型。

## 第 7 页：AI 可信回答机制

页面内容：

| 机制 | 作用 |
|---|---|
| EvidencePack | 收集题目、提交、课件、画像等证据。 |
| Reflection | 生成后自检教学性、引用和安全。 |
| Prompt Safety Filter | 过滤不合适输入和风险提示。 |
| Token 用量 | 控制成本和上下文长度。 |

讲解要点：

重点说明项目如何减少幻觉、泄题和无上下文回答。

## 第 8 页：核心功能三：课件 RAG 问答

页面内容：

流程：课件导入 → 页面切分 → 知识点抽取 → RAG 索引 → 学生提问 → 返回引用答案。

讲解要点：

1. 课件问答让 AI 回答贴合教师课程。
2. 引用页面和知识点能帮助学生回到原始材料。

## 第 9 页：核心功能四：课堂协作

页面内容：

1. 班级和成员。
2. 课堂和作业。
3. AI 智能出题。
4. 教师监控。

讲解要点：

系统不仅服务单个学生，也服务教师组织课堂教学。

## 答辩常见问题准备

| 问题 | 建议回答 |
|---|---|
| 为什么不用普通 ChatGPT 直接答疑？ | 普通 AI 缺少题目、提交、课件和学习者历史；Alethicode 基于真实学习上下文。 |
| 如何避免 AI 直接给答案？ | 通过阶段化 Tutor、EvidencePack、Prompt Safety Filter 和 Reflection 控制回答方式。 |
| RAG 的作用是什么？ | 让 AI 回答引用教师课件和知识点，减少脱离课堂的泛化回答。 |
| 系统最大难点是什么？ | 不是单个页面，而是 OJ、AI、RAG、课堂和运维多个子系统的一致协作。 |
| 项目是否可部署？ | 项目提供 Docker Compose、环境变量、健康检查和监控配置，但外部服务 Key 需要实际配置。 |
