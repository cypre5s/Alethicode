# Alethicode 功能演示视频脚本

> 建议时长：5-8 分钟  
> 视频比例：16:9  
> 建议分辨率：1920x1080  
> 录制方式：浏览器全屏 + 局部放大关键交互 + 后期补充字幕。  
> 说明：本脚本用于录制课程要求的功能演示视频。当前环境未直接生成视频文件，需按脚本录屏。

## 1. 演示准备

### 1.1 账号准备

| 账号 | 用途 |
|---|---|
| 学生账号 | 展示登录、做题、提交、AI Tutor、课件问答和学习复盘。 |
| 教师账号 | 展示班级、作业、课堂分析和 AI 出题。 |
| 管理员账号 | 展示题库、判题服务、语言包和可观测性。 |

### 1.2 数据准备

1. 准备一道简单 Python 题，例如求和、条件判断或循环统计。
2. 准备一份能触发错误的 Python 代码，用于展示 AI 错误诊断。
3. 准备一份能通过判题的 Python 代码，用于展示 AC 复盘。
4. 准备一个语言包和课件页面，用于展示课件问答引用。
5. 准备一个班级、作业和至少一名学生提交记录。
6. 准备管理端可访问的题目、用户、Judge Server 和 AI 可观测性页面。

### 1.3 环境检查

录制前执行或手工确认：

1. 前端页面可访问。
2. 后端健康检查正常。
3. PostgreSQL 和 Redis 正常。
4. Judge Server 可用。
5. LLM 和 Embedding Key 可用。
6. `tutor-graph` 和 `alethicode-rag` 健康。
7. 浏览器无广告拦截或插件干扰核心页面。

## 2. 视频结构

| 镜头 | 时长 | 内容 |
|---|---:|---|
| 1 | 30 秒 | 标题和项目简介。 |
| 2 | 60 秒 | 学生登录和题目浏览。 |
| 3 | 90 秒 | 在线评测：错误提交和正确提交。 |
| 4 | 90 秒 | AI Tutor：错误诊断和 AC 复盘。 |
| 5 | 60 秒 | 课件问答：基于课件引用回答。 |
| 6 | 60 秒 | 教师课堂：班级、作业和分析。 |
| 7 | 60 秒 | 管理端：题库、判题服务和可观测性。 |
| 8 | 30 秒 | 总结项目价值。 |

## 3. 详细分镜脚本

### 镜头 1：标题和项目简介

画面：

1. 显示项目标题页或 README。
2. 展示系统名称 Alethicode。

旁白：

“大家好，本视频演示 Alethicode 智能在线评测平台。它面向非计算机专业 Python 初学者，核心目标是把在线判题、AI 导学、课件问答和课堂管理结合起来，帮助学生从真实编程错误中学习。”

验收点：

1. 观众能理解项目定位。
2. 画面中出现项目名称和核心关键词。

### 镜头 2：学生登录和题目浏览

操作步骤：

1. 打开前端首页。
2. 点击登录。
3. 输入学生账号和密码。
4. 登录后进入题目列表 `/problem`。
5. 点击一道 Python 练习题。

旁白：

“首先演示学生端。学生登录后可以进入题库，选择适合当前学习阶段的题目。题目页展示题面、输入输出、样例和代码编辑器。”

验收点：

1. 登录成功。
2. 题目列表显示正常。
3. 题目详情和代码编辑器显示正常。

### 镜头 3：在线评测流程

操作步骤：

1. 在代码编辑器中输入一段有错误的代码。
2. 点击提交。
3. 查看提交结果，例如 Wrong Answer、Runtime Error 或 Compile Error。
4. 回到编辑器，输入正确代码。
5. 再次提交并查看 Accepted。
6. 打开提交详情页。

旁白：

“Alethicode 保留传统 OJ 的真实判题能力。学生提交代码后，后端会调用 Judge Server 执行沙箱评测，并记录运行结果。错误提交会保留错误信息，正确提交会返回 Accepted，这些数据后续会成为 AI Tutor 的学习证据。”

验收点：

1. 错误提交能产生判题记录。
2. 正确提交能得到 Accepted。
3. 提交详情能显示代码、语言、结果和运行信息。

### 镜头 4：AI Tutor 错误诊断和 AC 复盘

操作步骤：

1. 在题目页打开 AI Tutor 面板。
2. 基于错误提交询问：“我为什么错了？”
3. 展示 AI 分析错误原因和下一步提示。
4. 切换到通过后的状态或输入“帮我复盘这道题”。
5. 展示 AC 复盘、知识点总结和迁移练习建议。

旁白：

“AI Tutor 不是简单聊天框。它会结合当前题目、学生提交、判题错误、课件引用和学习者画像，按读题、构思、脚手架、编码、错误反馈、AC 复盘和迁移练习等阶段进行辅导。这样既能帮助学生理解错误，也避免直接给出完整答案。”

验收点：

1. AI Tutor 能读取当前题目和提交上下文。
2. 回答以提示和解释为主，不直接替学生完成。
3. AC 后能生成复盘和迁移建议。

### 镜头 5：课件问答

操作步骤：

1. 打开 `/language-pack-qa`。
2. 选择一个语言包。
3. 创建或进入课件问答会话。
4. 输入问题，例如“循环变量为什么要初始化？”
5. 展示 AI 回答和引用。
6. 点击引用页面预览。

旁白：

“课件问答用于解决通用 AI 脱离课堂的问题。系统会把教师课件处理成语言包和检索索引，学生提问后，RAG 服务会检索相关页面和知识点，AI 回答会尽量带上引用，方便学生回到原始材料学习。”

验收点：

1. 语言包列表可见。
2. 问答会话创建成功。
3. 回答包含课件引用。
4. 页面预览可打开。

### 镜头 6：教师课堂与作业

操作步骤：

1. 切换教师账号。
2. 进入班级列表。
3. 打开班级详情。
4. 展示作业、学生提交或课堂分析。
5. 展示 AI 生成题目或学情分析入口。

旁白：

“教师端用于组织真实课堂。教师可以创建班级、发布作业、查看学生提交和学情分析，也可以使用 AI 生成题目候选，再由教师人工审核。这样可以降低备题、批改和答疑成本。”

验收点：

1. 教师能访问班级页面。
2. 班级、作业或分析数据可见。
3. AI 出题或分析入口可展示。

### 镜头 7：管理端和可观测性

操作步骤：

1. 切换管理员账号。
2. 进入 `/admin/`。
3. 展示题目管理页面。
4. 展示 Judge Server 页面。
5. 展示 AI 配置或可观测性页面。
6. 展示使用统计或反馈页面。

旁白：

“管理端负责平台维护，包括题库、测试用例、用户、判题服务器、语言包、AI 配置和运行观测。系统接入 Prometheus、OpenTelemetry、Jaeger 和 Sentry/GlitchTip 等能力，方便定位 AI 和服务调用问题。”

验收点：

1. 管理员能进入管理端。
2. 题目、判题服务和配置页面可打开。
3. 可观测性或使用统计页面可展示。

### 镜头 8：总结

画面：

1. 回到首页或 PPT 总结页。
2. 展示“在线评测 + AI Tutor + 课件 RAG + 课堂协作”的闭环图。

旁白：

“总结来说，Alethicode 构建了一个面向初学者的智能编程教育闭环。它保留 OJ 的真实评测能力，又通过 AI Tutor、课件 RAG 和课堂协作提升学习体验，同时具备后台管理、测试和可观测性等工程能力。以上就是本项目的功能演示。”

## 4. 录制注意事项

1. 录制前清空浏览器无关标签，避免泄露密钥和个人信息。
2. 不展示 `.env`、API Key、数据库密码和服务器密钥。
3. 若 AI 响应较慢，可以提前生成一次，再录制稳定复现路径。
4. 每个镜头之间保留 1-2 秒停顿，便于剪辑。
5. 字幕使用简短句子，突出功能名称和关键价值。
6. 演示失败时不要临场排错，使用备用录屏或截图替换。
