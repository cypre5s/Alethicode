# Alethicode 软件需求规格说明书

> 文档编号：ALETHICODE-SRS-COURSE-2026  
> 版本：v1.0  
> 参考标准：ISO/IEC/IEEE 29148、ISO/IEC 25010  
> 适用对象：课程评审教师、项目开发人员、测试人员、答辩评委。

## 1. 引言

### 1.1 目的

本文档定义 Alethicode 智能在线评测平台的业务需求、用户需求、系统功能需求、非功能需求、数据需求、接口约束和验收准则，为概要设计、详细设计、测试计划和课程答辩提供基准。

### 1.2 项目定位

Alethicode 是面向非计算机专业 Python 初学者的 AI 智能在线评测平台。系统以在线判题为学习数据入口，结合 AI Tutor、课件 RAG、课堂协作和学习者画像，为学生提供可解释、可追踪、可复盘的编程学习支持，为教师提供题库、课堂、作业、学情和 AI 出题管理能力。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| OJ | Online Judge，在线评测系统。 |
| AI Tutor | 面向学生的阶段化 AI 编程导学助手。 |
| Language Pack | 课程语言包，包含课件、知识点、题目候选、页面和问答上下文。 |
| RAG | Retrieval-Augmented Generation，检索增强生成。 |
| KC | Knowledge Component，知识组件或知识点。 |
| EvidencePack | AI 回答前组织的题目、提交、课件、学习者画像等证据包。 |
| Reflection | AI 回答后的自检机制，用于检查教学性、引用、风险和完整性。 |
| Judge Server | 负责代码沙箱执行和判题的外部评测服务。 |
| Tutor Graph | LangGraph 驱动的 AI Tutor 工作流微服务。 |

## 2. 总体描述

### 2.1 产品视角

系统由 Vue 前端、Spring Boot 后端、Python 微服务和基础设施组成。前端提供学生端、教师端和管理端页面；后端提供账号、题目、提交、课堂、语言包、AI、系统配置和管理 API；`tutor-graph` 管理 AI Tutor 工作流；`alethicode-rag` 管理课件检索；Judge Server 执行代码评测；PostgreSQL、Redis、Memgraph、NATS 和 Temporal 支撑数据、缓存、图谱、消息和工作流。

### 2.2 用户角色

| 角色 | 目标 | 典型功能 |
|---|---|---|
| 游客 | 浏览公开入口、注册或登录 | 访问首页、登录、注册、找回密码。 |
| 学生 | 练习编程、获得辅导、复盘学习 | 做题、提交、查看反馈、使用 AI Tutor、课件问答、笔记本、错题复习、加入课堂。 |
| 教师 | 管理课堂和作业、查看学情、组织教学 | 创建班级、发布作业、监控课堂、查看分析、AI 生成题目、管理语言包。 |
| 管理员 | 维护平台、题库、用户和配置 | 用户管理、题目管理、判题服务、公告、系统配置、AI 配置、可观测性。 |
| 内部服务 | 跨服务调用 | Tutor Graph、RAG、质量检测、内部 AI 工具调用。 |

### 2.3 运行环境

| 层级 | 环境要求 |
|---|---|
| 后端 | Java 21、Maven 3.9+、Spring Boot 3.5.12。 |
| 前端 | Node.js >= 20.19.0、npm >= 10.8.2、Vue 3.5、Vite 7.1。 |
| 微服务 | Python 3.10/3.11、FastAPI、LangGraph、LightRAG。 |
| 数据与中间件 | PostgreSQL/pgvector、Redis、Memgraph、NATS、Temporal、Judge Server。 |
| 部署 | Docker Compose、Nginx、Prometheus、Jaeger、Grafana、Sentry/GlitchTip。 |

## 3. 业务需求

| 编号 | 业务需求 | 优先级 |
|---|---|---|
| BR-001 | 平台应帮助 Python 初学者完成从读题、编码到复盘的学习闭环。 | 高 |
| BR-002 | 平台应保留真实判题结果作为 AI 辅导和学习画像的基础。 | 高 |
| BR-003 | 平台应支持教师围绕课程课件和班级组织编程教学。 | 高 |
| BR-004 | 平台应降低教师备题、答疑、批改和学情分析的重复工作量。 | 高 |
| BR-005 | 平台应通过工程化手段保障可运行、可维护、可观测和可扩展。 | 高 |
| BR-006 | 平台应避免 AI 直接替学生完成作业，优先提供启发、提示和诊断。 | 高 |

## 4. 功能需求

### 4.1 账号与权限

| 编号 | 需求 |
|---|---|
| FR-ACC-001 | 系统应支持用户注册、登录、退出和个人资料查询。 |
| FR-ACC-002 | 系统应支持密码重置、邮箱变更、会话查询和会话删除。 |
| FR-ACC-003 | 系统应区分学生、教师、管理员等权限类型，并在前端和后端执行访问控制。 |
| FR-ACC-004 | 管理端应限制教师访问系统配置、用户管理、可观测性等管理员专属页面。 |
| FR-ACC-005 | 系统应通过 Redis Session 保存服务端会话，支持跨请求认证。 |

### 4.2 在线评测

| 编号 | 需求 |
|---|---|
| FR-OJ-001 | 学生应能查看题目列表、题目详情、难度、标签和相关课程信息。 |
| FR-OJ-002 | 学生应能在浏览器中编辑代码，至少支持 Python、C、C++、Java 等语言的编辑体验。 |
| FR-OJ-003 | 学生提交代码后，系统应将提交发送到 Judge Server 并返回判题状态。 |
| FR-OJ-004 | 系统应记录提交代码、语言、题目、用户、运行结果、时间和错误信息。 |
| FR-OJ-005 | 学生应能查看提交列表和提交详情。 |
| FR-OJ-006 | 管理员应能管理题目、测试用例、导入导出题目和判题服务器。 |

### 4.3 AI Tutor

| 编号 | 需求 |
|---|---|
| FR-AI-001 | 系统应在题目页提供 AI Tutor 入口，围绕当前题目和学生提交提供辅导。 |
| FR-AI-002 | AI Tutor 应支持阶段化学习流程，包括读题、构思、脚手架、编码、错误反馈、AC 复盘和迁移练习。 |
| FR-AI-003 | AI Tutor 应读取题目、提交、错误信息、学习者画像、课件引用和历史对话作为上下文。 |
| FR-AI-004 | AI Tutor 应支持会话查询、运行、检查点、恢复、对话、模式切换、压缩、分叉和中断响应。 |
| FR-AI-005 | AI Tutor 应支持 EvidencePack 和 Reflection，减少无依据回答和直接泄题。 |
| FR-AI-006 | AI Tutor 应支持 token 用量统计，便于控制上下文和成本。 |
| FR-AI-007 | 管理端应提供 AI 可观测性、提示变体、质量报告和工作流时间线等查看能力。 |

### 4.4 课件问答与语言包

| 编号 | 需求 |
|---|---|
| FR-LP-001 | 教师或管理员应能初始化语言包并导入课件材料。 |
| FR-LP-002 | 系统应对课件进行页面、文档、知识点和题目候选处理。 |
| FR-LP-003 | 学生应能基于语言包创建课件问答会话。 |
| FR-LP-004 | 课件问答应支持消息列表、发送消息、反馈、压缩、分叉、引用页面预览和视频生成任务。 |
| FR-LP-005 | RAG 服务应支持关键词和向量检索，并返回可追踪引用。 |
| FR-LP-006 | 语言包质量服务应支持参考解法 lint、自验证、样本同步和质量报告。 |

### 4.5 课堂协作与教师功能

| 编号 | 需求 |
|---|---|
| FR-CLS-001 | 教师应能创建和管理班级。 |
| FR-CLS-002 | 学生应能加入班级并查看班级详情。 |
| FR-CLS-003 | 教师应能创建课堂、作业和 AI 生成题目。 |
| FR-CLS-004 | 系统应支持课堂监控和学生风险识别。 |
| FR-CLS-005 | 系统应提供课堂分析、作业批改和误区分析能力。 |

### 4.6 学习复盘

| 编号 | 需求 |
|---|---|
| FR-REV-001 | 系统应为学生提供学习者笔记本，记录错题、复盘和学习记忆。 |
| FR-REV-002 | 系统应生成或维护知识点掌握度、练习热力图和推荐练习。 |
| FR-REV-003 | 系统应支持错题复习包和复习评分反馈。 |

### 4.7 管理与配置

| 编号 | 需求 |
|---|---|
| FR-ADM-001 | 管理员应能管理用户、公告、题目、测试用例和判题服务器。 |
| FR-ADM-002 | 管理员应能管理 AI 配置、系统路径、基础设施配置和 Beta 功能。 |
| FR-ADM-003 | 管理员应能查看使用统计、反馈、系统监控和 AI 观测面板。 |
| FR-ADM-004 | 系统应提供内部 API 供 Tutor Graph、RAG 和质量服务调用，并使用内部密钥校验。 |

## 5. 非功能需求

### 5.1 功能适合性

| 编号 | 需求 |
|---|---|
| NFR-FIT-001 | 系统功能应覆盖学生练习、教师教学、管理员运维和 AI 导学四类主流程。 |
| NFR-FIT-002 | AI 回答应与当前题目、提交和课件上下文一致，避免无上下文泛泛解释。 |

### 5.2 性能效率

| 编号 | 需求 |
|---|---|
| NFR-PERF-001 | 普通 API 请求应在合理时间内返回，耗时操作应使用异步任务、缓存或外部工作流处理。 |
| NFR-PERF-002 | AI 和 RAG 请求应支持熔断、重试、缓存和超时控制。 |
| NFR-PERF-003 | 数据库应对高频查询建立索引，迁移中包含热点索引和搜索优化。 |

### 5.3 可用性

| 编号 | 需求 |
|---|---|
| NFR-USAB-001 | 学生端应面向初学者，页面提示清晰，避免只展示底层错误码。 |
| NFR-USAB-002 | AI Tutor 应给出分步骤解释、提示和下一步行动建议。 |
| NFR-USAB-003 | 管理端应提供明确导航和权限提示。 |

### 5.4 可靠性

| 编号 | 需求 |
|---|---|
| NFR-REL-001 | 系统应通过 Redis Session、数据库事务和错误处理保障基本一致性。 |
| NFR-REL-002 | 外部服务不可用时应记录日志、返回清晰错误，并避免破坏主流程数据。 |
| NFR-REL-003 | AI Tutor 工作流应支持检查点和恢复，避免刷新页面导致会话丢失。 |

### 5.5 安全性

| 编号 | 需求 |
|---|---|
| NFR-SEC-001 | 系统应通过 Spring Security、会话认证和权限检查控制访问。 |
| NFR-SEC-002 | 对修改类请求应启用 CSRF 或等效保护。 |
| NFR-SEC-003 | 内部 API 应使用内部服务密钥校验，防止被普通用户调用。 |
| NFR-SEC-004 | 用户输入、Prompt 和上传材料应经过校验或过滤，降低注入、越权和敏感信息泄露风险。 |
| NFR-SEC-005 | 隐私功能应支持数据导出和个人数据删除请求。 |

### 5.6 可维护性

| 编号 | 需求 |
|---|---|
| NFR-MAINT-001 | 后端应按配置、控制器、服务、DTO、仓储、异常和工具分层。 |
| NFR-MAINT-002 | 前端应按学生端、管理端、页面、组件、API 和状态模块组织。 |
| NFR-MAINT-003 | 数据库 schema 变更必须通过 Flyway 迁移管理。 |
| NFR-MAINT-004 | 自动化测试应覆盖关键契约、服务逻辑和 UI 行为。 |

### 5.7 可移植性

| 编号 | 需求 |
|---|---|
| NFR-PORT-001 | 系统应支持本地开发和 Docker Compose 部署。 |
| NFR-PORT-002 | 外部 LLM、Embedding、Judge Server 等应通过配置接入，避免硬编码。 |

## 6. 数据需求

| 数据域 | 主要数据 |
|---|---|
| 用户域 | 用户、角色、权限、会话、邮箱、密码重置、隐私请求。 |
| 题库域 | 题目、标签、难度、测试用例、样例、提交、判题结果。 |
| AI 域 | Tutor 会话、运行、检查点、事件、对话消息、token 用量、学习者画像、记忆。 |
| 语言包域 | 语言包、文档、页面、知识点、题目候选、质量报告、视频任务。 |
| 课堂域 | 班级、成员、课堂、作业、提交、分析、风险检测。 |
| 运维域 | 系统配置、AI 配置、可观测性、反馈、审计日志。 |

## 7. 外部接口需求

| 外部系统 | 接口类型 | 说明 |
|---|---|---|
| Judge Server | HTTP/API | 提交代码、查询判题结果、管理判题节点。 |
| LLM Provider | HTTP/OpenAI-compatible | 生成 AI Tutor、课件问答、题目和解释。 |
| Embedding Provider | HTTP/OpenAI-compatible | 生成向量用于 RAG 检索。 |
| tutor-graph | HTTP/SSE/WebSocket 辅助 | 执行 LangGraph Tutor 工作流。 |
| alethicode-rag | HTTP | 课件索引、查询、健康检查。 |
| 邮件服务 | SMTP | 密码重置、通知邮件。 |
| 监控系统 | Prometheus/OTLP/Sentry | 指标、链路追踪、错误上报。 |

## 8. 验收准则

| 编号 | 验收场景 | 通过条件 |
|---|---|---|
| AC-001 | 学生注册登录并进入题目列表 | 登录成功，路由跳转正常，能看到题目。 |
| AC-002 | 学生完成一次代码提交 | 提交记录生成，判题状态可查询，详情可查看。 |
| AC-003 | 学生请求 AI Tutor 错误解释 | AI 能结合题目和提交错误给出分步提示。 |
| AC-004 | 学生使用课件问答 | 能创建会话、发送问题、返回带引用的回答。 |
| AC-005 | 教师创建班级和作业 | 班级可见，学生可加入，作业可分发。 |
| AC-006 | 管理员维护题目和测试用例 | 后台操作成功，学生端同步可见。 |
| AC-007 | 系统部署启动 | 前端、后端、数据库、Redis、Judge、RAG/Tutor 关键服务健康。 |
