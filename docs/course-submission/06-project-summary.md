# Alethicode 项目总结

> 文档编号：ALETHICODE-SUMMARY-COURSE-2026  
> 版本：v1.0  
> 适用范围：课程项目总结、答辩材料和结题说明。

## 1. 项目成果概述

Alethicode 完成了一个面向非计算机专业 Python 初学者的 AI 智能在线评测平台。系统不是单纯的题库或聊天机器人，而是以真实代码提交和判题结果为基础，把在线评测、AI Tutor、课件 RAG、课堂协作、学习者画像和后台管理整合到同一学习闭环中。

项目形成的主要成果包括：

1. 可运行的 Vue 3 前端，包含学生端 OJ、课件问答、学习复盘、课堂入口和管理端。
2. 可运行的 Spring Boot 后端，包含账号、题库、提交、AI、语言包、课堂、管理、合规和可观测性 API。
3. 两个 Python 微服务：`tutor-graph` 承担 LangGraph AI Tutor 工作流，`alethicode-rag` 承担课件 RAG 检索。
4. PostgreSQL/pgvector、Redis、Memgraph、NATS、Temporal、Judge Server 和监控组件组成的运行支撑。
5. 大量自动化测试资产和数据库 Flyway 迁移，支撑工程演进和回归验证。
6. 课程提交所需的项目计划、需求规格、概要设计、详细设计、测试计划与报告、项目总结、实训总结、PPT 内容稿和演示脚本。

## 2. 核心功能总结

| 模块 | 实现成果 |

| AI Tutor | 支持题目上下文、提交错误、学习者画像、阶段化导学、对话压缩、分叉、检查点和 WebSocket 恢复。 |

## 3. 技术成果总结

### 3.1 前端工程

前端采用 Vue 3.5、Vite 7.1、Vue Router 4、Vuex 4 和 Element Plus，配合 CodeMirror 6 构建浏览器代码编辑体验。学生端和管理端路由分离，学生端聚焦学习流程，管理端聚焦平台维护和教师/管理员工作台。

前端测试覆盖面较广，包含单元测试、契约测试、E2E、视觉回归和运行时测试，有助于减少 UI 回归风险。

### 3.2 后端工程

后端采用 Java 21 和 Spring Boot 3.5.12，包含 Web、JPA、Validation、Security、Redis Session、WebSocket、Actuator、Flyway、Spring AI、Resilience4j、Micrometer 和 Sentry 等能力。后端通过 Controller-Service-DTO-Repository 分层组织业务逻辑，并通过 Flyway 管理数据库迁移。

### 3.3 AI 与微服务

AI Tutor 不采用简单“一问一答”方式，而是围绕学生做题过程构建阶段化工作流。系统通过 EvidencePack 收集题目、提交、课件和学习者证据，通过 Reflection 对回答进行自检，通过 Tutor Graph 管理复杂工作流状态，通过 RAG 微服务提供课件检索增强。

### 3.4 数据与基础设施

系统使用 PostgreSQL 作为主数据库，pgvector 支撑向量检索，Redis 支撑会话和缓存，Memgraph 支撑 LightRAG 图存储，NATS 和 Temporal 支撑异步任务和工作流，Docker Compose 负责多服务编排。

## 4. 创新点

1. **真实判题 + AI 导学闭环**：AI 不脱离代码提交，而是基于真实判题错误进行诊断。
2. **面向初学者的阶段化 Tutor**：从读题到迁移练习分阶段辅导，降低学生直接抄答案的风险。
3. **课件 RAG 融入 OJ**：把教师课件、知识点和题目练习连接起来，使回答贴合课堂内容。
4. **学习者画像驱动反馈**：结合掌握度、误区、历史错误和学习记忆提供个性化提示。
5. **教师教学闭环**：从班级、作业、监控到 AI 出题和学情分析，支持真实课堂管理。
6. **工程化可观测性**：AI trace、token、质量报告、指标、日志和链路追踪共同支撑调试和运维。

## 5. 项目难点

| 难点 | 解决思路 |
|---|---|
| AI 回答容易泛化或泄题 | 使用 EvidencePack、Reflection、Prompt Safety Filter 和阶段化提示。 |
| RAG 与课件结构复杂 | 将语言包、文档、页面、知识点和索引任务拆分，使用 RAG 微服务处理检索。 |
| 外部服务依赖多 | 通过配置、健康检查、缓存、熔断和演示前 smoke test 降低风险。 |
| 课堂、AI、OJ 数据交叉 | 后端集中业务入口，数据库迁移和服务分层保持一致性。 |
| 前端交互复杂 | 通过组件化、路由分层、契约测试和 E2E 测试控制回归。 |

## 6. 当前不足

1. 系统依赖 LLM、Embedding、Judge Server 等外部服务，演示环境需要提前配置。
2. Career 模块已下线，历史迁移与文档中可能仍有残留表述，提交时应聚焦当前有效功能。
3. AI 输出质量受模型、Prompt、上下文和课件质量影响，需要持续评估。
4. 语言包初始化和 RAG 索引属于长任务，演示时不宜临场从零跑完整流程。
5. 全量压测和生产级 SLA 仍需进一步补充。

## 7. 后续改进计划

1. 完善课程级演示数据，准备稳定题目、课件、班级和学生账号。
2. 对 AI Tutor 增加更多学习效果评估指标，例如提示接受率、二次提交改善率和知识点迁移成功率。
3. 加强 RAG 引用质量评估，减少无关引用和漏召回。
4. 增加教师端课程模板和作业模板，提高教学复用效率。
5. 对高频接口进行压测，补充容量规划和性能基线。
6. 将课程提交文档转为学院模板 Word/PDF，并加入最终截图和测试结果。

## 8. 项目结论

Alethicode 已经形成一个较完整的智能编程教育平台原型。它覆盖了 OJ 的基础能力，也在此基础上进一步实现 AI 辅导、课件检索、课堂管理和学习者画像。项目在技术上体现了前后端分离、微服务协作、数据库迁移、自动化测试和可观测性，在教学上体现了“真实练习信号驱动个性化反馈”的设计思想。作为课程项目，Alethicode 具备较好的完整性、展示性和进一步扩展价值。
