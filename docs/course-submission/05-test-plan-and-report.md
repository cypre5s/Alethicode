# Alethicode 测试计划和测试报告

> 文档编号：ALETHICODE-TEST-COURSE-2026  
> 版本：v1.0  
> 参考标准：ISO/IEC/IEEE 29119、ISO/IEC 25010  
> 说明：本文档根据当前仓库测试结构和项目功能编写。课程提交前建议在实际演示环境中补充一次完整执行记录。

## 1. 测试目标

1. 验证在线评测主流程能够完成登录、题目查看、代码提交、判题结果查看。
2. 验证 AI Tutor 能基于题目、提交和学习上下文提供阶段化辅导。
3. 验证课件问答能够创建会话、发送消息、返回引用和预览课件页面。
4. 验证教师课堂、作业、AI 出题和监控分析功能可用。
5. 验证管理端题库、用户、判题服务、系统配置和可观测性功能具备基本可用性。
6. 验证系统满足安全、性能、可靠性、可维护性和部署可行性要求。

## 2. 测试范围

### 2.1 范围内

| 测试类别 | 覆盖内容 |
|---|---|
| 单元测试 | 服务类、工具类、策略类、上下文构造、AI 响应处理、RAG 客户端等。 |
| 控制器契约测试 | 后端 Controller 的请求参数、状态码、响应结构和权限行为。 |
| 集成测试 | 账号、公告、AI、语言包、提交、课堂和数据库相关流程。 |
| 前端单元/契约测试 | 路由、组件、API 契约、AI 卡片、课件问答、课堂页面和布局。 |
| E2E 测试 | 登录、导航、题目、课堂、AI Tutor 和视觉回归关键路径。 |
| 非功能测试 | 安全、可用性、性能、可观测性、恢复能力和部署检查。 |
| 手工验收 | 答辩演示路径、视频录制路径和课程验收场景。 |

### 2.2 范围外

1. 不对外部 LLM、Embedding、TTS 和 Judge Server 的内部实现进行白盒测试。
2. 不承诺在课程提交中完成大规模压测，只提供容量和性能风险分析。
3. 不覆盖所有历史迁移路径，只验证当前环境从空库迁移和核心表可用。

## 3. 测试环境

| 环境项 | 配置 |
|---|---|
| 操作系统 | Linux/WSL2 或 Ubuntu 22.04。 |
| 后端 | Java 21、Maven 3.9+、Spring Boot 3.5.12。 |
| 前端 | Node.js >= 20.19.0、npm >= 10.8.2。 |
| 数据库 | PostgreSQL 15/16 + pgvector。 |
| 缓存 | Redis 7。 |
| 微服务 | `tutor-graph`、`alethicode-rag`。 |
| 外部依赖 | Judge Server、LLM Provider、Embedding Provider。 |
| 浏览器 | Chromium/Chrome，Playwright 自动化使用 Chromium。 |

## 4. 测试依据

1. `README.md` 中的核心特性、技术栈和启动方式。
2. `backend/pom.xml` 中的依赖、插件和测试配置。
3. `frontend/package.json` 中的脚本、依赖和测试命令。
4. `services/tutor-graph/pyproject.toml` 与 `services/alethicode-rag/pyproject.toml`。
5. 后端 Controller、Service、数据库迁移和前端路由。
6. 本目录 `02-software-requirements-specification.md` 中的功能和非功能需求。

## 5. 测试策略

### 5.1 后端测试策略

| 层级 | 策略 |
|---|---|
| 单元测试 | 使用 JUnit、Mockito 或 Spring Boot Test 验证服务逻辑和工具类。 |
| 控制器测试 | 使用 MockMvc 验证 REST 契约、错误响应和权限边界。 |
| 集成测试 | 结合 Spring 上下文、数据库和测试配置验证跨层流程。 |
| 架构测试 | 使用 ArchUnit 验证包依赖边界。 |
| 外部服务测试 | 使用 stub、mock 或 respx 类似机制隔离外部 AI/RAG/Judge。 |

### 5.2 前端测试策略

| 层级 | 策略 |
|---|---|
| 单元测试 | 使用 Jest 验证组件渲染、工具函数和契约。 |
| 路由测试 | 验证学生端和管理端路由、权限守卫和跳转。 |
| E2E 测试 | 使用 Playwright 验证浏览器真实交互。 |
| 视觉测试 | 对关键页面做视觉比较，减少布局回归。 |
| 静态审计 | 对迁移替换、隐藏入口和运行时契约进行静态检查。 |

### 5.3 微服务测试策略

| 服务 | 策略 |
|---|---|
| tutor-graph | 使用 pytest、pytest-asyncio 和 httpx 验证工作流节点、API 和异步行为。 |
| alethicode-rag | 使用 pytest、pytest-asyncio、respx 和 httpx 验证索引、查询和外部调用。 |

## 6. 测试用例

### 6.1 账号与权限

| 用例编号 | 场景 | 步骤 | 预期结果 |
|---|---|---|---|
| TC-ACC-001 | 用户登录成功 | 输入正确账号密码并提交 | 返回成功，前端进入首页或原目标页面。 |

## 9. 推荐执行命令

### 9.1 后端

```bash
cd backend
mvn test
mvn clean compile -DskipTests
```

### 9.2 前端

```bash
cd frontend
npm ci
npm run lint
npm run typecheck
npm test
npm run test:e2e:auth
```

### 9.3 微服务

```bash
cd services/tutor-graph
python -m pip install -e ".[dev]"
python -m pytest -q

cd ../alethicode-rag
python -m pip install -e ".[dev]"
python -m pytest -q
```

### 10.3 质量结论

Alethicode 当前具备较完整的自动化测试基础：后端覆盖服务、控制器、集成、架构和 WebSocket，前端覆盖组件契约、路由、运行时和 E2E，微服务具备 pytest 入口。由于系统依赖外部 AI、Embedding、Judge Server 和数据库中间件，最终质量结论必须结合实际演示环境执行结果。课程答辩建议优先验证稳定路径，并对外部服务不可用风险准备截图或录屏备份。
